# @yaks/markdown

Parses GitHub Flavored Markdown (GFM) and renders it as element nodes for Preact
in a browser or `@yaks/tui` in a terminal. It uses Marked 18.0.6 for parsing,
never generates HTML strings, and does not store or fetch documents.

```ts
import { h } from 'preact'
import { Bold, Heading, Markdown } from '@yaks/markdown'

h(Markdown, { source: '# Hello\n\n**Shared** rendering.' })
h(Heading, { level: 2 }, h(Bold, null, 'Hello'))
```

`@yaks/markdown/structural` exports `parse`, `render`, `blocks`, `slugs`,
`headings`, `safeHref`, and the `Token` type without importing Preact. These
exports are also available from `@yaks/markdown`.

`parse(source, { breaks = true } = {})` returns the Markdown tokens. The default
turns single newlines into line breaks, suitable for chat messages. Use
`parse(source, { breaks: false })` for documents whose prose wraps across source
lines. `render(tokens, h)` targets the portable `@yaks/render` element
vocabulary, in a `div.Markdown` of its own; `blocks(tokens, h)` is the same
blocks without it, for a caller that holds them in its own element. `Markdown`
supplies Preact's `h` and uses the default parsing behavior. `Token` is
re-exported as a type. `safeHref(href)` permits relative URLs and `http`,
`https`, or `mailto` URLs, rejecting other explicit schemes and control
characters/ASCII spaces. It is also used by `Link` and Markdown rendering.
`Bold`, `Italic`, `Heading`, `Code`, `CodeBlock`, and `Link` are ordinary
semantic Preact components. Creating a node does not mount it: the application
passes it to Preact's browser renderer or a `@yaks/tui` screen. Terminal escape
sequences are generated by the terminal renderer, not this package.

Includes headings, emphasis, strike, inline/fenced code, links, lists/task
lists, quotes, rules, tables, and explicit/soft line breaks. HTML is literal
text; unsafe URL schemes are omitted; images become alt-text links rather than
remote loads. The harness applies Markdown to message prose through
query-matched transcript renderers. Tool calls/results stay literal (results
stay dim).

The terminal lays out tables with aligned columns, wrapping, and subtle borders.
Narrow tables switch to stacked header/value records. Markdown column alignment
is preserved in the shared semantic cells. Rendering does not fetch images or
other remote content.

Entity ids in prose are part of the grammar: a bare `T-123`, `#a1b2c3`, UUID or
whole SHA parses as a `ref` token, and `[words](T-123)` is a link to one. The
host says where each leads through `Refs`, `(id) => href | undefined`, passed as
`{ refs }` to `render`/`blocks` or, for `Markdown`, given by the `Host` context.
An id the host can open is an `a.Body_Ref` carrying `data-ref`; one it cannot
open stays its words, and with no host every id is words.

An eid (a UUID) in prose is never drawn whole. The host's `Ids`,
`(eid) => id | undefined`, passed as `{ ids }`, names it: the entity's id
(`P-1`) where the host already holds the entity or keeps its series in memory.
Otherwise it is drawn as its short handle from @yaks/id (`#a3f19c024b`). `Refs`
is asked about the drawn form, so a link never carries a whole uuid, and
`data-ref` keeps the eid. `drawn(source, ids)` does the same to the text itself,
for a reader of text such as a model or a printout: each eid written bare or as
a link's target becomes its drawn form, and code keeps its eids.
`shown(id, ids)` is the form one id is drawn as. A code span holding a hex word
(`` `1a2b3c4` ``) is asked about too, the way a commit is quoted. Code stays
literal. `mentions(tokens)` lists what a document points at, entities and
addresses, read as it is drawn. `flat` draws links, images and ids as words, for
a title (`MarkdownInline` takes it too). The same options take
`code(text, language)`, which colours a fenced block as runs of
`{ text, classes }`; without it code is plain.

The other way round, `typed(source)` lists the ids typed in prose that a store
would name an entity by, outside code: a human id (`T-12`) or a short handle of
ten or more hex characters, bare or as a link's target. `stored(source, eids)`
replaces each one `eids` answers with that eid, and leaves the rest as typed.
Given the text it replaces, `stored(source, eids, was)` swaps only the ids the
new text adds: one standing where `was` kept the same id as typed stays typed,
so `P-1 is very useful` is never bound to whatever later holds P-1, and one
standing where `was` held the eid it names takes that eid again.

`@yaks/markdown/graph` is the graph plugin built on them (@yaks/graph `Prose`):
a store composing it keeps each id typed in a property declaring `prose`
(@yaks/vocab) as the eid it names, so the text names the entity in any store and
under any number. A human id is swapped only where its letter is one the entity
prints with or carries, so `K-12` is not taken for whatever holds the number 12.
An id naming nothing stays as typed, and nothing is refused.

Run `deno task test packages/markdown` from the repository root for parser,
structural rendering and URL-safety tests.
