# `task context` v2 — sharp scope, project pulse, memory front-page

The injection-loop digest (`contextDigest`, src/client.ts) is the channel every
operator actually reads: once at boot (the SessionStart hook) and again as the
`## while you were away` rider on every task-tool call (the comms bus). So it is
the reliable place to tell an operator *what is happening in their project* —
more reliable than instant push, whose comment path is broken (below). This
redesign makes the digest sharply project-scoped, denser about project activity,
and an active front-page onto the fleet's shared memory.

## The three faults today

1. **Scope bleed — two mechanisms.**
   - *The `belongs()` catch-all* (the CrayonBloom bug). `lately` feeds from "any
     row with a `doc.title`", screened by `belongs()` (client.ts:646). But
     `belongs` only scopes task/memory/persona/project rows; **mail, session, and
     board docs fall through its `return true`** (line 654) and ride into every
     project's `lately` regardless of scope. CrayonBloom's scope resolves
     correctly to P-22 — the "UFOs" pollution is a UFOs *mail letter* (E-6939)
     plus foreign work-session briefs and boards. (UFOs *tasks* are correctly
     excluded.)
   - *Undefined scope* (a separate latent bug). A session whose cwd matches no
     `repo.path` (blank cwd, or a managed worktree outside its repo tree) gets
     `scope = undefined`, and then `belongs` returns `true` for EVERYTHING —
     including foreign tasks. `repoAt` also takes the FIRST prefix match, not the
     longest.

2. **Thin project activity.** `lately` lists fresh doc *titles* ranked by warmth.
   It never says "a comment landed on YOUR task" or "a task in your project moved
   to wip". The instant-push path for comments on claimed tasks is also broken
   (channel `filter.ts:186` only matches `target_eid == sessionEid`), so the poll
   digest is the ONLY reliable carrier of that signal — and it doesn't carry it.

3. **No memory front-page.** Global (unscoped) memories are the fleet's shared
   mind. Today they surface only as ≤3 warm titles buried in `lately`'s
   `### memory`, with no directive. Nothing invites the operator to read and
   internalize them.

## The redesign

### 1. Layered scope — repair at the identity level

`scope` resolves in priority order, first hit wins:

1. explicit `scope` arg (hook cwd, preview's project arg) — unchanged.
2. **cwd → repo, LONGEST `repo.path` prefix** (not first match). Guards against a
   broad `repo.path` swallowing an unrelated cwd.
3. **the worn persona's home** — `session.persona_eid → persona.home_eid`. A
   session wears a persona whose `home_eid` IS a project (types.ts:224); that is
   the operator's project even when their cwd is some scratch worktree. This is
   the CrayonBloom repair: identity, not filesystem, decides the project.
4. **the actor, when it stands for a project** — `session.actor_eid`, if it
   resolves to a `project` entity (a project standing in for its operator,
   types.ts:102).
5. undefined only if none of the above. When undefined, the fleet peek is HARD
   capped (a few lines), never a flood — an unplaceable session is a small
   window, not an open door.

New pure helper `scopeFor(all, sess, cwd, arg)` in client.ts, so every
caller-aware door (`contextDigest`, and later others) shares one resolution.

### 2. Project pulse — "what changed in your project"

A scoped activity tier replacing the title-only `lately` when a session stands
in a project. Two kinds of update, newest first, tightly capped:

- **Comments on your claimed tasks** since your last ack — the notification
  recovery. `T-42 💬 alice: can you rebase?` This is the same selection
  `notices()` already computes (comments on `mine` tasks after `acked_at`); the
  pulse surfaces the recent ones as standing context so a missed instant push
  never means a lost message. (It does NOT advance the ack cursor — recognition,
  not delivery.)
- **Recently-changed tasks in your project** — status moves and fresh work,
  scoped by `belongs`, warmth-ranked. `T-51 open→wip · Ship the sender`.

Memories move OUT of this tier into their own front-page (below). What remains of
`lately` is genuine project pulse, not a warm-title grab bag.

This is also what closes the `belongs()` bleed at the root. The pulse selects
specific entity TYPES scoped explicitly (tasks by `task.project_eid == scope`;
comments by the claim set), rather than "any titled doc, screened by a leaky
`belongs`". Mail keeps its own `## mail` line; boards and foreign session briefs
simply aren't pulse material — they never had a reason to be in the digest. So
the fix isn't to patch `belongs`'s catch-all; it's to stop feeding an
unclassified grab-bag in the first place. Same-project work-session briefs, if
kept, resolve their project via `repoAt(session.cwd)` — scoped, not
fall-through.

### 3. Memory front-page — investigate & adopt

A first-class section listing the warmest UNSCOPED memories (the fleet's
principles and discoveries) via `recallIndex` with a `scope_eid=` (empty) pred —
the same `M-1 0.96 feedback: title · 2×` line shape the persona index already
uses. Under a one-line persona directive:

> **## from the fleet** — read any that fit your work (`memory_recall <id>` —
> reading deepens recall) and adopt what helps.

Recognition-only: the index listing never bumps recall (the existing rule,
client.ts:636); the bump rides deliberate expansion. This makes the shared mind
an active invitation at every boot, not passive decoration.

### 4. Instant-push comment fix (companion)

The channel plugin's comment branch (`channels/tasks/filter.ts`) must accept a
comment whose `target_eid` is a task the served session CLAIMED, not only one
aimed at the session entity. `Ctx` gains the session's claimed-task eids (learned
from `claim` components in the plugin's `learn()`/`resolve()`), and the branch
tests `target_eid ∈ {sessionEid} ∪ claimedTaskEids` — mirroring `notices()`
(client.ts:890). This restores live delivery; the pulse (§2) is the durable
backstop under it.

### 5. Preview parity — two layers, one digest

The digest splits cleanly into a **project layer** (a function of `scope` alone)
and a **session layer** (needs the session identity), and renders them in order:

| layer   | sections                                                          |
| ------- | ----------------------------------------------------------------- |
| project | open-work suggestions · project pulse (changed tasks) · from the fleet · mail |
| session | claimed-by-you (replaces suggestions) · 💬 comments on your tasks · previously · unheard · while-you-were-away |

`task context` run in a project's repo (no session) renders ONLY the project
layer, scoped by cwd. Giving a session id ADDS the session layer — nothing in the
project layer changes. So a preview shows *exactly* what that project's operator
sees, minus the session extras — by construction, not by coincidence.

Invariant, pinned by test: the project-layer lines of
`contextDigest(snap, undefined, now, P)` equal the project-layer subset of
`contextDigest(snap, someSession, now, P)` for the same scope `P`.

## Budget

The 35-line cap must breathe. Raise to ~48 and rebalance:

| tier              | lines |
| ----------------- | ----- |
| claimed / open    | 4–5   |
| project pulse     | 6–8   |
| from the fleet    | 5–6   |
| previously        | 4     |
| mail / unheard    | 1–2   |

Dense markdown, no blank lines spend a line (CommonMark). Every line earns its
place; when the room runs out, claimed work wins, then pulse, then fleet memory.

## Test surface (pure seams)

- `scopeFor`: arg > longest-prefix cwd > persona home > actor-project > undefined,
  as a case table.
- project pulse: comment-on-claimed and changed-in-project selected; other-project
  activity excluded (the CrayonBloom regression, pinned).
- memory front-page: only `scope_eid`-empty memories; warmth order; no recall bump.
- `filter.ts` comment branch: claimed-task target accepted, foreign target dropped.

## Out of scope

Fixing the sweep (`notices()` targeting is correct). Reworking mail. Changing how
claims or personas are minted.
